# FaWave 多维力感知采集与安全监测平台

FaWave 是一款基于 Python 的商业级数据采集与可视化平台，专门用于以太网四通道力传感设备的数据接收、解析、实时绘图和本地保存。

## 核心功能
- **全中文化专业 UI**：提供浅色/深色双主题，适应科研演示与长时间监控场景。
- **高性能实时波形**：基于 pyqtgraph 渲染的实时电压及三维力解耦曲线。
- **真实设备与仿真模式**：支持连接真实 TCP 采集板，或脱机启动仿真演示模式，数据流转线程完全解耦，确保高频采集不丢帧。
- **完整协议解析**：自定义配置字节序和协议结构，支持实时提取 35 字节完整原始帧。
- **三维力解耦算法**：等价移植了 Keil `app_ForceOut.c` 核心算法。包含开机自动建立基线、输入/输出级 EMA 滤波、死区处理及自动环境温漂归零功能。
- **数据本地持久化**：支持以 CSV/XLSX 格式导出，包含时间戳和原始十六进制帧，且采用缓冲和文件追加技术，解决大文件写入性能问题。

## 三维力解耦
此模块对应算法逻辑移植自嵌入式版本 (Firmware/STM32F4_ForceFBAcq_V01/App/app_ForceOut.c)。
位置位于：`FaWave_Python/src/force/force_decoder.py`。
- **功能特性**：
  1. 输入电压4路采集;
  2. 开机自动建基线 (Startup Warmup);
  3. 输入数据3点中值滤波 + EMA平滑;
  4. 3×4 矩阵解耦产生 Fx/Fy/Fz;
  5. 稳定窗口检测死区判定与自动基线更新;
  6. 手动清零接口;
- **单位说明**：
  UI层面展示 CH1~CH4 使用 mV，但解耦算法内部运算默认应用 V 作为单位。换算比率 `input_scale_to_v` 可在 JSON 自由配置。

## 运行环境
推荐使用 Python 3.10 或更高版本。

## 安装依赖
1. 克隆代码仓库。
2. 在项目根目录下执行：
   ```bash
   pip install -r requirements.txt
   ```

## 启动软件
执行入口脚本打开上位机：
```bash
python main.py
```

## 通信参数
当前验证通过的真实硬件通信参数默认配置如下：

- **设备 IP**：192.168.1.82
- **电脑 IP**：192.168.1.81
- **端口**：16008
- **通信方式**：TCP
- **采集方式**：每次请求返回一帧 (Per Request)
- **请求间隔**：20 ms
- **返回帧长度**：35 字节
- **请求帧 (HEX)**：`5A A5 82 01 0D 00 00 00 00 00 00 FF FF`
- **解析方式**：`frame[5:21]`，小端 float32 (`<ffff`)

## 数据保存与日志
勾选“启用本地存储”后，每次建立连接都将把采集到的完整数据保存至选择的路径。
- **默认路径**：程序目录/Data/FaWave_Data_YYYYMMDD_HHMMSS.csv
- **格式**：支持 CSV (推荐用于长时间记录) 和 XLSX。
- **日志**：软件运行日志（包含通信建立和协议解析错误详情）默认保存在根目录下的 `logs/FaWave_YYYYMMDD.log`，方便事后排查异常。

## 推荐使用方式
1. **正式实验**：
   - 解耦后端选择 **C语言后端**；
   - 采集模式选择 **真实设备**；
   - 连接后保持传感器无载静止约 5 秒；
   - 待解耦状态变为“已启用”或“死区内”后再开始实验。
2. **无硬件演示**：
   - 采集模式选择 **仿真演示**；
   - 解耦后端可选择 C语言后端或 Python移植；
   - 前 6 秒为自动建基线阶段；
   - 6 秒后仿真力曲线开始出现动态变化。
3. **算法调试**：
   - 解耦后端选择 **Python移植**；
   - 使用 `tools/force_validation` 对比 C 输出；
   - 验证通过后再用于正式实验。

## 三维力解耦术语说明
- **三维力解耦**: 传感器实际采集到的是 4 路电压信号，我们希望得到 Fx、Fy、Fz 三个方向的力。解耦就是把 4 路电压变化转换成 3 个方向力的过程。
- **原始电压 CH1~CH4**: 四个传感通道直接采集到的电压值，是最原始的数据。
- **基线 / 零点**: 传感器在无外力、静止状态下的参考电压。后续所有力的计算都以这个参考电压为零点。
- **开机建基线**: 软件连接后，先让传感器保持无载静止几秒钟，自动记录当前稳定电压作为零点。这个过程完成前，Fx/Fy/Fz 会保持为 0。
- **差分电压 d1~d4**: 当前滤波后的电压减去基线电压，表示每个通道相对于零点发生了多少变化。
- **解耦矩阵**: 一个 3×4 的标定矩阵，用于把 d1~d4 转换为 Fz、Fx、Fy。矩阵来自传感器标定实验。
- **Fz/Fx/Fy 顺序**: C 程序内部矩阵行顺序是 Fz、Fx、Fy，而界面显示通常是 Fx、Fy、Fz，因此程序中必须做正确映射，不能混淆。
- **EMA 滤波**: 一种平滑算法，可以减少噪声和波动。EMA 会让输出更稳定，但响应会稍微变慢。
- **三点中值滤波**: 用最近 3 个点中的中间值作为输入，可以抑制偶发尖峰干扰。
- **死区**: 当计算出来的力非常小，例如小于 0.5 N 时，软件会直接显示为 0。这可以避免零点附近的小噪声导致力值一直抖动。死区不是错误，是为了让显示更稳定。
- **死区内**: 表示解耦算法已经正常运行，但当前力值太小，被死区规则置零。因此 Fx/Fy/Fz 为 0 不代表算法没运行。
- **自动基线更新**: 当软件判断传感器长时间处于稳定且小力状态时，会慢慢修正零点，用来抵消零点漂移。
- **三维力归零**: 用户手动把当前状态设为新的零点。适用于传感器安装后或实验前重新校准零点。
- **C语言后端**: 直接调用由原始 Keil C 算法编译出的 DLL，最接近下位机算法，推荐正式实验使用。
- **Python移植后端**: 把 C 算法翻译成 Python 后运行，便于调试和跨平台使用，需要通过 C-Python 对比验证。
- **验证状态**: 用于说明当前 Python 移植算法是否已经和 C 参考算法进行过误差对比。如果显示“未验证”，说明结果只能用于调试，不能作为最终实验结果。

## 常见问题排查 (FAQ)
1. **问题：为什么 Fx/Fy/Fz 一直显示 0？**
   **可能原因**：
   - 解耦算法未启用；
   - 软件正在开机建基线（前5秒）；
   - 传感器没有受力，或当前力值在死区范围内；
   - 仿真演示模式仍处于 0~6 秒的建基线阶段；
   - 输入单位配置错误；
   - C DLL 加载失败；
   - 真实设备启动时没有保持无载静止，导致基线无法建立。

   **解决方法**：
   - 查看右侧“解耦状态”，等待 5~6 秒；
   - 点击操作面板上的“三维力归零”；
   - 检查 config 文件中的 `input_scale_to_v` 和 `backend` 是否正确。

2. **问题：显示“帧长度错误，期望 35 字节”**
   - 请前往 `config/default_config.json` 检查 `frame_length` 字段。

3. **主界面为什么不显示 UDP 设置？**
   - 当前真实设备已经验证为 TCP 连接。UDP 协议逻辑仍旧保留在底层通信模块中供调试，但正式生产环境仅暴露经过验证的真实设备(TCP)和仿真演示模式。
